#### Merits & Demerits of Object literals:

##### Merits:
Object literals solved the problem of multiple unmanageable variables from lecture 1, by wrapping related data & functions together for a particular user.

##### Demerits:
```
var userOne = {
    email: 'ryu@ninjas.com',
    name: 'Ryu',
    login(){
        console.log(this.email, 'has logged in');
    },
    logout(){
        console.log(this.email, 'has logged out');
    }
};

var prop = 'name'

// userOne.email = 'ryu2k18@ninjas.com';
// userOne['email'] = 'ryu2k18@ninjas.com';
// userOne[prop] = 'Ryuke';

// console.log(userOne);

userOne.age = 25;
userOne.logInfo = function(){
    console.log(this.name, this.age, this.email);
};
```

1. In above snippet, even though we encapsulated the data inside a object literal, we can access & modify the properties outside the object literal.

2.  If I have to create a `userTwo`, in this syntax, I have to add `login` & `logout` to userTwo as well. What If there's a bug in `login` function, then we have to update the logic inside all objects of user.

3. For updating the properties the code is still outside the object literal, which is not following encapsulation concept.

4. Also imagine you have to create 1000s of users and after defining the user object literal at line 1 and aat line 1000 someone updated the properties of user object. Hence this is till unmanageable.

5. Also If all users is having same properties (email, name) and functions (login & logout), there'll be a lot of code duplication in object literals syntax.
