In PostgreSQL, these are the **four fundamental JOIN types** you'll commonly use:

1. **CROSS JOIN**
2. **INNER JOIN**
3. **LEFT JOIN**
4. **RIGHT JOIN**

Let's understand each with a simple example.

---

## Sample Tables

Suppose we have:

### `employees`

| emp_id | name  | dept_id |
| -----: | ----- | ------: |
|      1 | Raj   |      10 |
|      2 | Priya |      20 |
|      3 | Amit  |      30 |
|      4 | Sneha |    NULL |

### `departments`

| dept_id | dept_name |
| ------: | --------- |
|      10 | IT        |
|      20 | HR        |
|      40 | Finance   |

We'll use these tables for all four joins.

---

# 1. CROSS JOIN

A **CROSS JOIN** returns **every possible combination** of rows from both tables.

### Syntax

```sql
SELECT *
FROM employees
CROSS JOIN departments;
```

If:

* `employees` has 4 rows
* `departments` has 3 rows

Result:

**4 × 3 = 12 rows**

### Example

```text
Raj    × IT
Raj    × HR
Raj    × Finance

Priya  × IT
Priya  × HR
Priya  × Finance

Amit   × IT
Amit   × HR 
Amit   × Finance

Sneha  × IT
Sneha  × HR
Sneha  × Finance
```

There is **no matching condition**.

### Think of it as

> "Combine everyone with everyone."

---

# 2. INNER JOIN

An **INNER JOIN** returns only rows where the join condition matches in **both tables**.

### Syntax

```sql
SELECT e.emp_id,
       e.name,
       d.dept_name
FROM employees e
INNER JOIN departments d
    ON e.dept_id = d.dept_id;
```

### Result

| emp_id | name  | dept_name |
| -----: | ----- | --------- |
|      1 | Raj   | IT        |
|      2 | Priya | HR        |

Why?

```text
employees              departments

10  ────────────────→  10 IT
20  ────────────────→  20 HR
30  ────────────────X  30 doesn't exist
NULL ───────────────X  NULL doesn't match
                       40 Finance has no employee
```

So only matching rows survive.

### Think of it as

> "Give me employees who have a matching department."

---

# 3. LEFT JOIN

A **LEFT JOIN** returns:

* **All rows from the left table**
* Matching rows from the right table
* `NULL` when there is no match

### Syntax

```sql
SELECT e.emp_id,
       e.name,
       d.dept_name
FROM employees e
LEFT JOIN departments d
    ON e.dept_id = d.dept_id;
```

### Result

| emp_id | name  | dept_name |
| -----: | ----- | --------- |
|      1 | Raj   | IT        |
|      2 | Priya | HR        |
|      3 | Amit  | NULL      |
|      4 | Sneha | NULL      |

Notice that **Amit and Sneha are still present** even though they don't have a matching department.

That's because `employees` is the **LEFT table**.

```text
LEFT TABLE              RIGHT TABLE

employees               departments
   │                         │
   │                         │
   └────── LEFT JOIN ────────┘
   
   ALL employees
   +
   matching departments
```

### Think of it as

> "Give me ALL employees, and their department if they have one."

This is one of the most frequently used joins.

---

# 4. RIGHT JOIN

A **RIGHT JOIN** is the opposite of a LEFT JOIN.

It returns:

* **All rows from the right table**
* Matching rows from the left table
* `NULL` when there is no match

### Syntax

```sql
SELECT e.emp_id,
       e.name,
       d.dept_name
FROM employees e
RIGHT JOIN departments d
    ON e.dept_id = d.dept_id;
```

### Result

| emp_id | name  | dept_name |
| -----: | ----- | --------- |
|      1 | Raj   | IT        |
|      2 | Priya | HR        |
|   NULL | NULL  | Finance   |

`Finance` is included even though there is no employee belonging to department 40.

Why?

Because `departments` is the **RIGHT table**.

### Think of it as

> "Give me ALL departments, and their employee if they have one."

---

# All 4 Compared

| JOIN           | What does it return?                |
| -------------- | ----------------------------------- |
| **CROSS JOIN** | Every possible combination          |
| **INNER JOIN** | Only matching rows                  |
| **LEFT JOIN**  | All left rows + matching right rows |
| **RIGHT JOIN** | All right rows + matching left rows |

Using our example:

```text
                 Employees       Departments
                 ─────────       ───────────
CROSS JOIN       ALL × ALL       → 12 combinations

INNER JOIN       Matching        → Raj, Priya

LEFT JOIN        ALL employees   → Raj, Priya, Amit, Sneha

RIGHT JOIN       ALL departments → IT, HR, Finance
```

---

## LEFT JOIN vs RIGHT JOIN

These two are essentially mirror images.

This:

```sql
FROM employees e
LEFT JOIN departments d
    ON e.dept_id = d.dept_id
```

is equivalent to:

```sql
FROM departments d
RIGHT JOIN employees e
    ON e.dept_id = d.dept_id
```

The result is the same.

### Practical convention

Most developers prefer **LEFT JOIN** because it is easier to read:

```sql
FROM employees e
LEFT JOIN departments d
```

rather than:

```sql
FROM employees e
RIGHT JOIN departments d
```

So **RIGHT JOIN is less commonly used**; you can usually rewrite it as a LEFT JOIN by swapping the table order.

---

## One Important Concept

The table written immediately after `FROM` is your **left table**:

```sql
FROM employees e
LEFT JOIN departments d
```

```text
        LEFT              RIGHT
          ↓                 ↓
FROM employees       LEFT JOIN departments
```

Therefore:

```sql
LEFT JOIN  → preserve left table
RIGHT JOIN → preserve right table
INNER JOIN → preserve only matches
CROSS JOIN → no matching condition; all combinations
```

A useful way to remember them:

**INNER = intersection**
**LEFT = everything on left**
**RIGHT = everything on right**
**CROSS = everything with everything**
