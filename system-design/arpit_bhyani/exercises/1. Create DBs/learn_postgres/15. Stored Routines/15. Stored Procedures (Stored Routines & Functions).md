Absolutely. In PostgreSQL, **Stored Procedures** and **User-Defined Functions (UDFs)** are both database-side programs, but they serve different purposes.

A good way to understand them is:

> **Function → calculate/return something**
> **Procedure → perform an operation**

---

# 1. User-Defined Function

A **function** is a reusable piece of SQL/PL/pgSQL logic that **returns a value or a set of rows**.

You create one using:

```sql
CREATE FUNCTION
```

### Simple example

Suppose we have:

```sql
CREATE TABLE employees (
    emp_id SERIAL PRIMARY KEY,
    fname VARCHAR(50),
    salary NUMERIC(10,2)
);
```

Create a function to calculate annual salary:

```sql
CREATE OR REPLACE FUNCTION annual_salary(monthly_salary NUMERIC)
RETURNS NUMERIC
LANGUAGE plpgsql
AS $$
BEGIN
    RETURN monthly_salary * 12;
END;
$$;
```

Now call it:

```sql
SELECT annual_salary(50000);
```

Result:

```text
 annual_salary
---------------
     600000
```

So the function behaves somewhat like a programming-language function:

```text
annual_salary(50000)
       ↓
   50000 × 12
       ↓
     600000
```

---

# 2. Function Can Use Tables

Functions become much more useful when they work with database data.

For example:

```sql
CREATE OR REPLACE FUNCTION get_employee_salary(
    employee_id INT
)
RETURNS NUMERIC
LANGUAGE plpgsql
AS $$
DECLARE
    emp_salary NUMERIC;
BEGIN
    SELECT salary
    INTO emp_salary
    FROM employees
    WHERE emp_id = employee_id;

    RETURN emp_salary;
END;
$$;
```

Call it:

```sql
SELECT get_employee_salary(1);
```

The function:

1. Receives employee ID
2. Queries `employees`
3. Gets the salary
4. Returns the salary

---

# 3. Function Returning Multiple Rows

A PostgreSQL function can also return a table.

```sql
CREATE OR REPLACE FUNCTION get_it_employees()
RETURNS TABLE (
    emp_id INT,
    fname VARCHAR,
    salary NUMERIC
)
LANGUAGE plpgsql
AS $$
BEGIN
    RETURN QUERY
    SELECT e.emp_id, e.fname, e.salary
    FROM employees e
    WHERE e.dept = 'IT';
END;
$$;
```

You can query it like a table:

```sql
SELECT * FROM get_it_employees();
```

This is one of the powerful features of PostgreSQL functions.

---

# 4. Stored Procedure

A **stored procedure** is a database-side program primarily designed to **perform actions**.

You create one using:

```sql
CREATE PROCEDURE
```

For example, suppose we want to give an employee a ₹5,000 raise.

```sql
CREATE OR REPLACE PROCEDURE give_raise(
    employee_id INT,
    raise_amount NUMERIC
)
LANGUAGE plpgsql
AS $$
BEGIN
    UPDATE employees
    SET salary = salary + raise_amount
    WHERE emp_id = employee_id;
END;
$$;
```

Call it using:

```sql
CALL give_raise(1, 5000);
```

Then:

```sql
SELECT *
FROM employees
WHERE emp_id = 1;
```

The employee's salary has been increased.

---

# 5. Function vs Procedure

This is the most important distinction.

| Feature                      | Function                | Procedure                     |
| ---------------------------- | ----------------------- | ----------------------------- |
| Create with                  | `CREATE FUNCTION`       | `CREATE PROCEDURE`            |
| Call with                    | `SELECT` / expressions  | `CALL`                        |
| Must return a value?         | **Yes**                 | **No**                        |
| Can return rows?             | ✅ Yes                   | ❌ Not as a function result    |
| Main purpose                 | Calculate / retrieve    | Perform operations            |
| Can be used inside `SELECT`? | ✅                       | ❌                             |
| Can modify data?             | ✅ Depending on function | ✅                             |
| Transaction control          | Restricted              | More flexible                 |
| Typical use                  | Calculations, queries   | Business operations/workflows |

---

# 6. Function vs Procedure — Simple Analogy

Think about an ATM.

### Function

You ask:

> "What is my account balance?"

```sql
SELECT get_balance(101);
```

It **returns something**.

```text
get_balance(101)
      ↓
   ₹50,000
```

### Procedure

You ask:

> "Transfer ₹10,000 from account 101 to account 102."

```sql
CALL transfer_money(101, 102, 10000);
```

It **performs an operation**.

```text
transfer_money()
       ↓
Debit account 101
       ↓
Credit account 102
```

You don't primarily call it to get a calculated result.

# 7. Real-World Example

Suppose we have:

```sql
CREATE TABLE accounts (
    account_id INT PRIMARY KEY,
    holder_name VARCHAR(100),
    balance NUMERIC(12,2)
);
```

Data:

| account_id | holder_name | balance |
| ---------: | ----------- | ------: |
|        101 | Raj         |   50000 |
|        102 | Priya       |   30000 |

### Function — Check balance

```sql
CREATE OR REPLACE FUNCTION get_balance(
    acc_id INT
)
RETURNS NUMERIC
LANGUAGE plpgsql
AS $$
DECLARE
    current_balance NUMERIC;
BEGIN
    SELECT balance
    INTO current_balance
    FROM accounts
    WHERE account_id = acc_id;

    RETURN current_balance;
END;
$$;
```

Call:

```sql
SELECT get_balance(101);
```

Result:

```text
50000
```

---

### Procedure — Transfer money

```sql
CREATE OR REPLACE PROCEDURE transfer_money(
    from_account INT,
    to_account INT,
    amount NUMERIC
)
LANGUAGE plpgsql
AS $$
BEGIN

    UPDATE accounts
    SET balance = balance - amount
    WHERE account_id = from_account;

    UPDATE accounts
    SET balance = balance + amount
    WHERE account_id = to_account;

END;
$$;
```

Call:

```sql
CALL transfer_money(101, 102, 10000);
```

Now:

| account_id | holder_name | balance |
| ---------: | ----------- | ------: |
|        101 | Raj         |   40000 |
|        102 | Priya       |   40000 |

---

# 8. Why Use Them?

Without functions/procedures, your application might contain logic like:

```text
React
   ↓
Node.js
   ↓
SQL queries
   ↓
Database
```

Some database logic can instead live inside PostgreSQL:

```text
React
   ↓
Node.js
   ↓
CALL transfer_money(...)
   ↓
PostgreSQL Procedure
   ↓
Multiple SQL operations
```

This can be useful when you want **centralized database logic**, especially for complex operations involving multiple tables.

# 9. Function Syntax to Remember

The general structure is:

```sql
CREATE OR REPLACE FUNCTION function_name(
    parameter_name datatype
)
RETURNS return_datatype
LANGUAGE plpgsql
AS $$
BEGIN

    -- logic

    RETURN value;

END;
$$;
```

Example:

```sql
CREATE OR REPLACE FUNCTION add_numbers(
    a INT,
    b INT
)
RETURNS INT
LANGUAGE plpgsql
AS $$
BEGIN
    RETURN a + b;
END;
$$;
```

Usage:

```sql
SELECT add_numbers(10, 20);
```

Result:

```text
30
```

---

# 10. Procedure Syntax

```sql
CREATE OR REPLACE PROCEDURE procedure_name(
    parameter_name datatype
)
LANGUAGE plpgsql
AS $$
BEGIN

    -- perform operations

END;
$$;
```

Example:

```sql
CREATE OR REPLACE PROCEDURE update_salary(
    employee_id INT,
    new_salary NUMERIC
)
LANGUAGE plpgsql
AS $$
BEGIN

    UPDATE employees
    SET salary = new_salary
    WHERE emp_id = employee_id;

END;
$$;
```

Usage:

```sql
CALL update_salary(1, 75000);
```

## One important PostgreSQL concept

You'll often see:

```sql
LANGUAGE plpgsql
```

**PL/pgSQL** is PostgreSQL's procedural programming language. It gives you programming constructs such as:

```text
IF / ELSE
LOOP
FOR
WHILE
DECLARE
BEGIN / END
EXCEPTION
```

For example:

```sql
IF salary > 50000 THEN
    -- do something
ELSE
    -- do something else
END IF;
```

So your learning path can be:

```text
SQL
 │
 ├── Queries
 ├── Joins
 ├── Subqueries
 ├── Aggregation
 │
 └── PL/pgSQL
       │
       ├── Variables
       ├── IF / ELSE
       ├── Loops
       ├── Functions
       ├── Procedures
       └── Exception Handling
```

**In short:**

> **Function = "Give me a result."**
> **Procedure = "Do this operation."**

One nuance: PostgreSQL functions **can also perform `INSERT`, `UPDATE`, and `DELETE`**, so "function = read-only" is not correct. The stronger distinction is **how they're invoked and whether they return a function result / participate in expressions**.
