# 1. Simple `CASE`

A **simple CASE** compares one column/expression against specific values.

### Example: Convert department names to short codes

```sql
SELECT
    emp_id,
    fname,
    dept,
    CASE dept
        WHEN 'IT' THEN 'Information Technology'
        WHEN 'HR' THEN 'Human Resources'
        WHEN 'Finance' THEN 'FIN'
        WHEN 'Marketing' THEN 'MKT'
        ELSE 'Other'
    END AS department_name
FROM employees;
```

Result:

```text
emp_id | fname  | dept      | department_name
-------+--------+-----------+------------------------
1      | Raj    | IT        | Information Technology
2      | Priya  | HR        | Human Resources
3      | Arjun  | IT        | Information Technology
4      | Suman  | Finance   | FIN
5      | Kavita | HR        | Human Resources
6      | Amit   | Marketing | MKT
...
```

### Pattern

```sql
CASE column
    WHEN value1 THEN result1
    WHEN value2 THEN result2
    ELSE result
END
```

---

# 2. Searched `CASE`

A **searched CASE** evaluates conditions.

This is probably the most commonly used form.

### Categorize employees based on salary

```sql
SELECT
    emp_id,
    fname,
    salary,
    CASE
        WHEN salary >= 60000 THEN 'High'
        WHEN salary >= 50000 THEN 'Medium'
        ELSE 'Low'
    END AS salary_category
FROM employees;
```

Your data would produce:

```text
fname  | salary  | salary_category
-------+---------+----------------
Raj    | 50000   | Medium
Priya  | 45000   | Low
Arjun  | 55000   | Medium
Suman  | 60000   | High
Kavita | 47000   | Low
Amit   | 52000   | Medium
Neha   | 48000   | Low
Rahul  | 53000   | Medium
Anjali | 61000   | High
Vijay  | 50000   | Medium
```

### Important

The conditions are evaluated **top to bottom**.

For:

```sql
CASE
    WHEN salary >= 60000 THEN 'High'
    WHEN salary >= 50000 THEN 'Medium'
    ELSE 'Low'
END
```

A salary of `60000` matches the first condition, so PostgreSQL doesn't continue checking the second one.

# 3. `CASE` in `SELECT`

We've already used this above, but let's make it slightly more practical.

### Show full name and experience category

```sql
SELECT
    emp_id,
    fname || ' ' || lname AS full_name,
    hire_date,
    CASE
        WHEN hire_date < DATE '2020-01-01' THEN 'Experienced'
        WHEN hire_date < DATE '2021-01-01' THEN 'Mid-level'
        ELSE 'Recent Hire'
    END AS experience_category
FROM employees;
```

Here:

```sql
fname || ' ' || lname
```

combines first and last name.

# 4. `CASE` in `WHERE`

You **can** use `CASE` inside `WHERE`.

For example, suppose you want different salary requirements for different departments:

```sql
SELECT
    emp_id,
    fname,
    dept,
    salary
FROM employees
WHERE
    CASE
        WHEN dept = 'IT' THEN salary >= 52000
        WHEN dept = 'HR' THEN salary >= 46000
        WHEN dept = 'Finance' THEN salary >= 60000
        ELSE salary >= 50000
    END;
```

This means:

```text
IT        → salary >= 52000
HR        → salary >= 46000
Finance   → salary >= 60000
Others    → salary >= 50000
```

For your data, employees such as:

```text
Arjun  IT        55000
Suman  Finance   60000
Kavita HR        47000
Amit   Marketing 52000
Rahul  IT        53000
Anjali Finance   61000
```

would satisfy the condition.

### However

For complicated conditions, I'd generally prefer a direct boolean expression:

```sql
WHERE
       (dept = 'IT'        AND salary >= 52000)
    OR (dept = 'HR'        AND salary >= 46000)
    OR (dept = 'Finance'   AND salary >= 60000)
    OR (dept NOT IN ('IT', 'HR', 'Finance') AND salary >= 50000);
```

The `CASE` version is useful for **learning**, but isn't always the clearest way to write the query.

# 5. `CASE` in `ORDER BY`

This is a very useful real-world application.

### Put IT employees first

```sql
SELECT
    emp_id,
    fname,
    dept,
    salary
FROM employees
ORDER BY
    CASE
        WHEN dept = 'IT' THEN 1
        ELSE 2
    END,
    fname;
```

Result ordering:

Neha
Rahul
Raj

Other employees
---------------

Anjali
Kavita
Priya
Suman
Vijay

You can think of:

```sql
CASE
    WHEN dept = 'IT' THEN 1
    ELSE 2
END
```

as creating a **temporary sorting priority**.

# 6. Multiple priorities in `ORDER BY`

Suppose you want:

SELECT

# 7. `CASE` in `UPDATE`

Now let's modify actual data.

### Give employees different salary increments

```sql
UPDATE employees
SET salary =
    CASE
        WHEN dept = 'IT' THEN salary * 1.10
        WHEN dept = 'HR' THEN salary * 1.08
        WHEN dept = 'Finance' THEN salary * 1.07
        ELSE salary * 1.05
    END;
```

This means:

```text
IT         → +10%
HR         → +8%
Finance    → +7%
Marketing  → +5%
```

⚠️ This actually changes your database.

For learning, you can first see what would happen with:

```sql
SELECT
    fname,
    dept,
    salary AS old_salary,
    CASE
        WHEN dept = 'IT' THEN salary * 1.10
        WHEN dept = 'HR' THEN salary * 1.08
        WHEN dept = 'Finance' THEN salary * 1.07
        ELSE salary * 1.05
    END AS new_salary
FROM employees;
```

This is safer for experimentation.

# 13. `CASE` in `HAVING`

You can even use it with `HAVING`.

For example, show departments whose average salary is at least ₹50,000:

```sql
SELECT
    dept,
    AVG(salary) AS avg_salary
FROM employees
GROUP BY dept
HAVING
    CASE
        WHEN AVG(salary) >= 50000 THEN TRUE
        ELSE FALSE
    END;
```

Although this is valid, the simpler version is:

```sql
HAVING AVG(salary) >= 50000;
```

So again, `CASE` is possible, but don't use it when a simpler expression communicates the intention better.

# 14. Nested `CASE`

You can put a `CASE` inside another `CASE`.

### Classify employees based on department AND salary

```sql
SELECT
    fname,
    dept,
    salary,
    CASE
        WHEN dept = 'IT' THEN
            CASE
                WHEN salary >= 55000 THEN 'Senior IT'
                ELSE 'Junior IT'
            END

        WHEN dept = 'Finance' THEN
            CASE
                WHEN salary >= 60000 THEN 'Senior Finance'
                ELSE 'Junior Finance'
            END

        ELSE 'Other Department'
    END AS employee_level
FROM employees;
```

For example:

```text
Arjun  IT       55000 → Senior IT
Raj    IT       50000 → Junior IT
Suman  Finance 60000 → Senior Finance
Priya  HR       45000 → Other Department
```

Nested `CASE` works, but don't overuse it because readability decreases quickly.

# 17. Correlated subquery + `CASE`

This combines two important concepts.

### Compare each employee's salary with their department's average

```sql
SELECT
    e.fname,
    e.dept,
    e.salary,
    CASE
        WHEN e.salary > (
            SELECT AVG(e2.salary)
            FROM employees e2
            WHERE e2.dept = e.dept
        )
        THEN 'Above Department Average'

        WHEN e.salary < (
            SELECT AVG(e2.salary)
            FROM employees e2
            WHERE e2.dept = e.dept
        )
        THEN 'Below Department Average'

        ELSE 'At Department Average'
    END AS salary_position
FROM employees e;
```

This is a more advanced example combining:

```text
CASE
  +
Correlated Subquery
```

# 18. `CASE` vs `COALESCE`

Since your `mob` column has `NULL`, you'll encounter this frequently.

Using `CASE`:

```sql
SELECT
    fname,
    CASE
        WHEN mob IS NULL THEN 'Not Available'
        ELSE mob
    END AS mobile
FROM employees;
```

But PostgreSQL provides a simpler function:

```sql
SELECT
    fname,
    COALESCE(mob, 'Not Available') AS mobile
FROM employees;
```

So:

> **`CASE` is for general conditional logic.**
> **`COALESCE` is specifically convenient for replacing `NULL`.**

# Complete CASE Cheat Sheet

| Usage          | Example                                   |
| -------------- | ----------------------------------------- |
| Simple CASE    | `CASE dept WHEN 'IT' THEN ... END`        |
| Searched CASE  | `CASE WHEN salary > 50000 THEN ... END`   |
| `SELECT`       | Create calculated/derived values          |
| `WHERE`        | Conditional filtering                     |
| `ORDER BY`     | Custom sorting priority                   |
| `UPDATE`       | Conditional value modification            |
| `NULL`         | `WHEN mob IS NULL THEN ...`               |
| `COUNT`        | Conditional counting                      |
| `SUM`          | Conditional summation                     |
| `GROUP BY`     | Group based on calculated category        |
| `HAVING`       | Conditional group filtering               |
| Nested CASE    | CASE inside CASE                          |
| With subquery  | Conditional result based on another query |
| With `ANY/ALL` | Used alongside subquery comparisons       |

### The most important distinction

There are really **two CASE syntaxes** you should memorize:

```sql
-- Simple CASE
CASE expression
    WHEN value1 THEN result1
    WHEN value2 THEN result2
    ELSE result
END
```

and:

```sql
-- Searched CASE
CASE
    WHEN condition1 THEN result1
    WHEN condition2 THEN result2
    ELSE result
END
```

For PostgreSQL/SQL development, **searched `CASE` is the one you'll probably use most often** because it can express arbitrary conditions.
