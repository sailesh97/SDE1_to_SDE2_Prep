In SQL/PostgreSQL, **`ALTER`** is used to modify the structure of an existing database object—most commonly a table.

Think:

> **`CREATE` → create structure**
> **`ALTER` → change structure**
> **`DROP` → remove structure**

## Common `ALTER TABLE` queries in PostgreSQL

Assume:

```sql
CREATE TABLE employees (
    id SERIAL PRIMARY KEY,
    name VARCHAR(100),
    salary NUMERIC,
    department_id INT
);
```

### 1. Add a column (ALTER + ADD)

```sql
ALTER TABLE employees
ADD COLUMN email VARCHAR(255);
```

Add multiple columns:

```sql
ALTER TABLE employees
ADD COLUMN phone VARCHAR(20),
ADD COLUMN date_of_birth DATE;
```

---

### 2. Drop a column (ALTER + DROP)

```sql
ALTER TABLE employees
DROP COLUMN phone;
```

Safely:

```sql
ALTER TABLE employees
DROP COLUMN IF EXISTS phone;
```

---

### 3. Rename a column (ALTER + RENAME)

```sql
ALTER TABLE employees
RENAME COLUMN name TO full_name;
```

---

### 4. Change column data type (ALTER + ALTER)

```sql
ALTER TABLE employees
ALTER COLUMN salary TYPE DECIMAL(12,2);
```

If PostgreSQL cannot automatically convert the existing values, you can specify `USING`:

```sql
ALTER TABLE employees
ALTER COLUMN salary TYPE INTEGER
USING salary::INTEGER;
```

---

### 5. Set `NOT NULL`

```sql
ALTER TABLE employees
ALTER COLUMN email SET NOT NULL;
```

⚠️ This fails if existing rows contain `NULL` in `email`.

---

### 6. Remove `NOT NULL`

```sql
ALTER TABLE employees
ALTER COLUMN email DROP NOT NULL;
```

---

### 7. Set a default value

```sql
ALTER TABLE employees
ALTER COLUMN salary SET DEFAULT 0;
```

Now:

```sql
INSERT INTO employees (name)
VALUES ('John');
```

will use `0` for salary.

---

### 8. Remove a default

```sql
ALTER TABLE employees
ALTER COLUMN salary DROP DEFAULT;
```

---

## 9. Add a constraint

### UNIQUE

```sql
ALTER TABLE employees
ADD CONSTRAINT employees_email_unique
UNIQUE (email);
```

### CHECK

```sql
ALTER TABLE employees
ADD CONSTRAINT salary_positive
CHECK (salary > 0);
```

### FOREIGN KEY

```sql
ALTER TABLE employees
ADD CONSTRAINT employees_department_fk
FOREIGN KEY (department_id)
REFERENCES departments(id);
```

---

## 10. Drop a constraint

```sql
ALTER TABLE employees
DROP CONSTRAINT salary_positive;
```

---

## 11. Rename a table

```sql
ALTER TABLE employees
RENAME TO staff;
```

---

## 12. Add a primary key

```sql
ALTER TABLE employees
ADD CONSTRAINT employees_pkey
PRIMARY KEY (id);
```

---

## 13. Change table owner

PostgreSQL also supports:

```sql
ALTER TABLE employees
OWNER TO postgres;
```

---

# PostgreSQL `ALTER TABLE` Cheat Sheet

| Requirement       | Query                            |
| ----------------- | -------------------------------- |
| Add column        | `ADD COLUMN`                     |
| Remove column     | `DROP COLUMN`                    |
| Rename column     | `RENAME COLUMN ... TO`           |
| Change datatype   | `ALTER COLUMN ... TYPE`          |
| Add `NOT NULL`    | `ALTER COLUMN ... SET NOT NULL`  |
| Remove `NOT NULL` | `ALTER COLUMN ... DROP NOT NULL` |
| Add default       | `ALTER COLUMN ... SET DEFAULT`   |
| Remove default    | `ALTER COLUMN ... DROP DEFAULT`  |
| Add constraint    | `ADD CONSTRAINT`                 |
| Remove constraint | `DROP CONSTRAINT`                |
| Rename table      | `RENAME TO`                      |
| Change owner      | `OWNER TO`                       |

### Important distinction

`ALTER` is **not a function** and generally isn't an operator either.

It is a **SQL command/statement**, and `ALTER TABLE` is a specific form of that statement.

For your PostgreSQL learning sequence, you can think of the major SQL command categories as:

```text
SQL Commands
│
├── DDL → CREATE, ALTER, DROP, TRUNCATE
│
├── DML → INSERT, UPDATE, DELETE
│
├── DQL → SELECT
│
├── DCL → GRANT, REVOKE
│
└── TCL → COMMIT, ROLLBACK, SAVEPOINT
```

This classification is useful for understanding where `ALTER` fits in PostgreSQL.
