In **PostgreSQL**, the `LIKE` clause is used to search for a **pattern within text/string values**.

### Basic syntax

```sql
SELECT *
FROM users
WHERE username LIKE 'sai%';
```

Here `%` is a wildcard.

### Main `LIKE` wildcards

| Pattern | Meaning                                  | Example                               |
| ------- | ---------------------------------------- | ------------------------------------- |
| `%`     | Any number of characters, including zero | `'sai%'` → `sai`, `sailesh`, `sai123` |
| `_`     | Exactly one character                    | `'s_i'` → `sai`, `sbi`, `sxi`         |

### Common examples

**1. Starts with `sai`**

```sql
WHERE username LIKE 'sai%'
```

Matches:

```text
sai
sailesh
sai123
```

**2. Ends with `esh`**

```sql
WHERE username LIKE '%esh'
```

Matches:

```text
sailesh
ramesh
mahesh
```

**3. Contains `ai`**

```sql
WHERE username LIKE '%ai%'
```

Matches:

```text
sailesh
raihan
```

**4. Exactly one character between `s` and `i`**

```sql
WHERE username LIKE 's_i'
```

Matches:

```text
sai
sbi
sci
```

### `LIKE` vs `ILIKE` in PostgreSQL

PostgreSQL also provides **`ILIKE`**, which performs a **case-insensitive** pattern match.

```sql
SELECT *
FROM users
WHERE username ILIKE 'sai%';
```

This matches:

```text
sai
Sai
SAI
Sai123
```

Whereas:

```sql
WHERE username LIKE 'sai%'
```

is case-sensitive.

### `NOT LIKE`

You can also exclude patterns:

```sql
SELECT *
FROM users
WHERE username NOT LIKE 'admin%';
```

This returns users whose username **doesn't start with `admin`**.

### One important performance point

A query like:

```sql
WHERE username LIKE '%sai%'
```

usually **can't efficiently use a normal B-tree index**, because the pattern starts with `%`.

But:

```sql
WHERE username LIKE 'sai%'
```

can potentially use an appropriate B-tree index.

For PostgreSQL, if you frequently need arbitrary substring searches (`%sai%`), **trigram indexes (`pg_trgm`)** are worth learning.
