**Crow’s Foot Notation** is a visual notation used in **ER (Entity-Relationship) diagrams** to show **relationships and cardinality between entities**.

It is called *Crow’s Foot* because the symbol for **“many”** looks like a crow’s three-pronged foot.

### 1. Basic symbols

| Symbol          | Meaning         |             |
| --------------- | --------------- | ----------- |
| `               | `               | Exactly one |
| `O`             | Zero / optional |             |
| `⟨crow's foot⟩` | Many            |             |

These symbols can be combined:

| Notation | Meaning      |             |             |
| -------- | ------------ | ----------- | ----------- |
| `        |              | `           | Exactly one |
| `O       | `            | Zero or one |             |
| `        | <`           | One or many |             |
| `O<`     | Zero or many |             |             |

Think of it as answering **two questions**:

> **Is participation optional?** → `O` or `|`
> **How many can participate?** → `|` or crow's foot

---

## 2. Example: Customer → Orders

Suppose:

> A customer can place many orders.
> Every order belongs to exactly one customer.

The relationship can be represented as:

```text
CUSTOMER                    ORDER
   |                          |
   |                          |
   ||------------------------|<
```

More conceptually:

```text
CUSTOMER  ||───────────────<  ORDER
          1                 MANY
```

Meaning:

* One **Customer** can have **many Orders**
* One **Order** belongs to exactly **one Customer**

This is a **1:N (one-to-many)** relationship.

---

## 3. Optionality makes it more powerful

Suppose:

> A customer may or may not have orders.

Then:

```text
CUSTOMER  ||──────────────O<  ORDER
          1                0..many
```

This means:

**Customer side**

* Exactly one customer

**Order side**

* Zero or many orders

So:

```text
Customer → 0..many Orders
```

---

## 4. Common relationships

### One-to-One

```text
PERSON  ||────────────||  PASSPORT
         1            1
```

One person has exactly one passport, and one passport belongs to exactly one person.

---

### One-to-Many

```text
DEPARTMENT  ||────────────O<  EMPLOYEE
             1              0..many
```

A department can have zero or many employees.

An employee belongs to exactly one department.

---

### Many-to-Many

```text
STUDENT  O<────────────O<  COURSE
        0..many        0..many
```

A student can enroll in many courses, and a course can have many students.

In a **relational database**, this would normally be implemented using a junction/associative table:

```text
STUDENT
   |
   | 1
   |
   |< 
STUDENT_COURSE
   |
   |>
   |
   | 1
COURSE
```

## 5. Crow's Foot vs Chen notation

Since you've been learning **ER modeling**, this distinction is useful.

|              | Crow's Foot           | Chen                      |
| ------------ | --------------------- | ------------------------- |
| Entity       | Rectangle             | Rectangle                 |
| Relationship | Line                  | Diamond                   |
| Attribute    | Usually inside entity | Oval                      |
| "Many"       | Crow's foot           | `N`                       |
| Common usage | Database/ERD design   | Conceptual ER modeling    |
| Example      | `CUSTOMER \|< ORDER`  | Customer — places — Order |

So, **Crow's Foot is essentially a notation style for drawing ERDs**, particularly useful for showing **cardinality and optionality** clearly.

### The key thing to remember

```text
O  = zero
|  = one
<  = many
```

Therefore:

```text
O|  = 0 or 1
||  = exactly 1
O<  = 0 or many
|<  = 1 or many
```

These four combinations cover most Crow's Foot relationships you'll encounter.
