# Integrity Constraints in DBMS

**Integrity constraints** are rules applied to a database to ensure that the **data stored is accurate, valid, and consistent**.

Think of them as **rules that prevent invalid data from entering the database**.

### Example

Suppose we have:

```sql
CREATE TABLE users (
    user_id INT,
    name VARCHAR(100),
    email VARCHAR(100),
    age INT
);
```

Without constraints, someone could insert:

```text
user_id = NULL
name = NULL
age = -50
```

Integrity constraints can prevent such invalid data.

---

## Types of Integrity Constraints

The major types are:

| Constraint                 | Purpose                                | Example                              |
| -------------------------- | -------------------------------------- | ------------------------------------ |
| **Domain Constraint**      | Ensures values are from a valid domain | Age must be an integer               |
| **NOT NULL Constraint**    | Prevents NULL values                   | Name cannot be NULL                  |
| **UNIQUE Constraint**      | Prevents duplicate values              | Email must be unique                 |
| **PRIMARY KEY Constraint** | Uniquely identifies each row           | `user_id`                            |
| **FOREIGN KEY Constraint** | Maintains relationships between tables | `post.user_id` must exist in `users` |
| **CHECK Constraint**       | Enforces a condition                   | Age must be ≥ 18                     |
| **DEFAULT Constraint**     | Provides a default value               | Status defaults to `'active'`        |

---

# 1. Domain Constraint

A **domain** defines the set of valid values an attribute can have.

For example:

```sql
age INT
```

means `age` should contain integer values.

You could further restrict it:

```sql
age INT CHECK (age >= 0)
```

Now:

```text
25    → Valid
0     → Valid
-10   → Invalid
"ABC" → Invalid
```

### Simple definition

> **Domain constraint ensures that an attribute contains values from a valid domain.**

---

# 2. NOT NULL Constraint

Ensures that a column **cannot contain NULL**.

```sql
CREATE TABLE users (
    user_id INT,
    name VARCHAR(100) NOT NULL
);
```

This is invalid:

```sql
INSERT INTO users (user_id, name)
VALUES (1, NULL);
```

Because `name` cannot be NULL.

### Important

`NULL` means **unknown/missing value**. It is not the same as:

```text
0
""
"NULL"
```

---

# 3. UNIQUE Constraint

Ensures that values in a column are **not duplicated**.

Example:

```sql
CREATE TABLE users (
    user_id INT,
    email VARCHAR(100) UNIQUE
);
```

You cannot have:

```text
user_id | email
--------|----------------
1       | a@gmail.com
2       | b@gmail.com
3       | a@gmail.com ❌
```

The third row violates the `UNIQUE` constraint.

---

# 4. Primary Key Constraint

A **PRIMARY KEY** uniquely identifies every row in a table.

Example:

```sql
CREATE TABLE users (
    user_id INT PRIMARY KEY,
    name VARCHAR(100)
);
```

Therefore:

```text
user_id | name
--------|-------
1       | Alice
2       | Bob
3       | Charlie
```

is valid.

But:

```text
user_id | name
--------|-------
1       | Alice
1       | Bob       ❌
```

is invalid because two rows cannot have the same primary key.

### Primary key has two important properties:

**1. Unique**

```text
1
2
3
```

No duplicates.

**2. NOT NULL**

```text
NULL → ❌
```

A primary key cannot be NULL.

---

# 5. Foreign Key Constraint

This is one of the **most important constraints in relational databases**.

A foreign key ensures that a value in one table refers to an existing value in another table.

Consider:

### `users`

```text
user_id | name
--------|------
1       | Alice
2       | Bob
3       | John
```

### `posts`

```text
post_id | user_id | content
--------|---------|---------
101     | 1       | Hello
102     | 2       | Hi
```

Here:

```text
posts.user_id
      ↓
users.user_id
```

We can define:

```sql
CREATE TABLE posts (
    post_id INT PRIMARY KEY,
    user_id INT,
    content VARCHAR(255),

    FOREIGN KEY (user_id)
        REFERENCES users(user_id)
);
```

Now this is invalid:

```sql
INSERT INTO posts
VALUES (103, 99, 'Hello');
```

because:

```text
user_id = 99
```

doesn't exist in `users`.

This maintains **referential integrity**.

---

# 6. CHECK Constraint

A `CHECK` constraint ensures that a value satisfies a particular condition.

Example:

```sql
CREATE TABLE employees (
    employee_id INT PRIMARY KEY,
    age INT CHECK (age >= 18)
);
```

Therefore:

```text
age = 25  → ✅
age = 18  → ✅
age = 15  → ❌
```

Another example:

```sql
salary DECIMAL(10,2) CHECK (salary > 0)
```

---

# 7. DEFAULT Constraint

Provides a value automatically when the user doesn't provide one.

```sql
CREATE TABLE users (
    user_id INT PRIMARY KEY,
    name VARCHAR(100),
    status VARCHAR(20) DEFAULT 'active'
);
```

If we execute:

```sql
INSERT INTO users (user_id, name)
VALUES (1, 'Alice');
```

The database automatically stores:

```text
user_id | name  | status
--------|-------|--------
1       | Alice | active
```

---

# Entity Integrity vs Referential Integrity

These two are particularly important in DBMS theory.

### Entity Integrity

> **Primary key cannot be NULL.**

Every row must have a way to be uniquely identified.

```text
users
----------------
user_id (PK)
1
2
3
NULL ❌
```

### Referential Integrity

> **Foreign key must refer to an existing primary/unique key value in the referenced table** (unless NULL is allowed).

```text
users
user_id
-------
1
2
3

posts
user_id
-------
1  ✅
2  ✅
99 ❌
```

---

# Complete Example

Let's combine several constraints:

```sql
CREATE TABLE users (
    user_id INT PRIMARY KEY,
    name VARCHAR(100) NOT NULL,
    email VARCHAR(100) UNIQUE,
    age INT CHECK (age >= 18),
    status VARCHAR(20) DEFAULT 'active'
);
```

And:

```sql
CREATE TABLE posts (
    post_id INT PRIMARY KEY,
    user_id INT NOT NULL,

    FOREIGN KEY (user_id)
        REFERENCES users(user_id)
);
```

Now the database enforces:

```text
users
 │
 │ PRIMARY KEY
 ↓
user_id
 │
 │ FOREIGN KEY
 ↓
posts.user_id
```

So:

* `user_id` must be unique → **PRIMARY KEY**
* `name` cannot be missing → **NOT NULL**
* `email` cannot be duplicated → **UNIQUE**
* `age` must be ≥ 18 → **CHECK**
* `status` defaults to `active` → **DEFAULT**
* `posts.user_id` must refer to an existing user → **FOREIGN KEY**

---

## Easy way to remember

```text
Integrity Constraints
│
├── Domain Constraint
│   └── Is the value valid?
│
├── NOT NULL
│   └── Can the value be missing?
│
├── UNIQUE
│   └── Can the value be duplicated?
│
├── PRIMARY KEY
│   └── Can this uniquely identify a row?
│
├── FOREIGN KEY
│   └── Does the referenced row exist?
│
├── CHECK
│   └── Does the value satisfy a condition?
│
└── DEFAULT
    └── What value should be used if none is provided?
```

### The two big concepts

**Entity Integrity → Primary Key**

> Every row must have a unique, non-NULL identity.

**Referential Integrity → Foreign Key**

> Relationships between tables must remain valid.

These are especially important when you move from the **ER Model → Relational Model → SQL table design**, which fits directly with the DBMS topics you've been learning.
